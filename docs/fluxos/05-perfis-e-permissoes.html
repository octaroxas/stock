Perfis e permissões

Cada perfil reúne permissões, e um usuário pode acumular perfis. Marque os perfis de uma pessoa à esquerda e veja à direita as telas que ela passa a ter. Mais abaixo está a matriz completa e um teste de ações, que mostra por que a permissão sozinha não basta: quem pode aprovar um pedido também precisa não ser quem o pediu.

Perfis por município (Spatie Permission com teams)

  • Os perfis são por tenant: a tabela roles tem team_id igual ao tenant_id. Um município pode ajustar os seus sem afetar os outros.
  • As permissões são as mesmas para todos: são definidas pelo código, uma por ação do sistema, e ficam numa tabela global.
  • Os perfis são criados junto com o tenant, já com as permissões da matriz acima.
  • A atribuição de perfil ao usuário (model_has_roles) também leva o tenant.
// middleware, depois de descobrir o tenant pelo subdomínio
setPermissionsTeamId($tenant->id);

// ao criar o tenant
foreach (array_keys(PerfisPadrao::matriz()) as $nome) {
    $perfil = Role::create(['name' => $nome]);
    $perfil->syncPermissions(PerfisPadrao::matriz()[$nome]);
}

public function autorizar(User $user, Pedido $pedido): bool
{
    return $user->can('pedidos.autorizar')
        && $pedido->status === StatusPedido::EnviadoParaAprovacao
        && $pedido->solicitante_id !== $user->id
        && $this->etapaAtualDesigna($pedido, $user);
}

Perguntas para levar à SEMTRAS

  1. Estoque e Distribuição são pessoas diferentes? A análise trata os dois como o setor de Compras. Se for a mesma equipe, os dois perfis podem virar um.
  2. O solicitante vê só os pedidos do seu setor ou também os que ele fez em outro setor onde já trabalhou?
  3. Quem pode cancelar um pedido, e até quando? A matriz assume: o próprio solicitante, enquanto não houve entrega.
  4. Quem recebe a permissão de entrada fora de contrato? Sugestão: o responsável do Estoque, concedida pelo Administrador, cada caso registrado na auditoria.
  5. Quem faz o papel de Administrador no município? Ele não consta no PDF, mas alguém precisa cadastrar usuários e setores.
  6. Os dois setores autorizadores são a NSUAS 1 e a NSUAS 2, numa etapa só: basta um servidor de qualquer um deles. A Policy consulta a etapa configurada. Falta definir se um deles pode rever a decisão do outro.
