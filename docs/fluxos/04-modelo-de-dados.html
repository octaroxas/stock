Os módulos continuam independentes?

      
Conferência feita sobre as chaves estrangeiras acima: cada módulo só pode apontar para o núcleo e para os módulos de que declara depender. Se uma FK passar disso, a linha fica vermelha.

Como o tenant chega ao banco

        
    
          
  1. O middleware lê o subdomínio e descobre o tenant.
    2. 
          
  2. Dentro da transação, ele grava o id na conexão: select set_config('app.tenant_id', ?, true).
    3. 
          
  3. O global scope do trait BelongsToTenant filtra pelo mesmo id. É a primeira barreira.
    4. 
          
  4. A policy de RLS é a segunda: mesmo uma query escrita sem o scope só enxerga as linhas do município.
    5. 
          
  5. Sem o app.tenant_id definido, a comparação resulta em nulo e nenhuma linha aparece.
    6. 
        

        
Jobs de fila e comandos do Artisan também precisam definir o tenant antes de tocar no banco.

      

      

        
Cuidados com o isolamento

        
    
          
  • A aplicação conecta com um usuário sem BYPASSRLS e que não é dono das tabelas. Por isso o FORCE ROW LEVEL SECURITY.
    • 
          
  • Para impedir uma FK que ligue linhas de municípios diferentes, as tabelas filhas podem usar FK composta: (tenant_id, pedido_id) referenciando um único (tenant_id, id).
    • 
          
  • Os únicos são sempre por município: dois municípios podem ter o pedido 2026/000001 e o mesmo CNPJ de fornecedor.
    • 
          
  • A tabela audits só aceita inserção: o usuário da aplicação perde UPDATE, DELETE e TRUNCATE.
    •

Pontos em aberto que mexem no modelo

      
    
        
  1. Regra das duas autorizações. O modelo já aceita qualquer uma: etapas em ordem, com regra “qualquer” ou “todos” e escopo por tipo de item (fluxo_etapas). A escolha da SEMTRAS vira só configuração.
    2. 
        
  2. Quem recebe tem sempre login? Por enquanto entregas aceita recebedor_id ou recebedor_nome. Se for sempre servidor com login, o nome em texto sai.
    3. 
        
  3. Forma de assinatura do termo. termos.forma_assinatura e arquivo_path cobrem o impresso com upload do escaneado. A assinatura eletrônica pode pedir outras colunas (data, IP, certificado).
